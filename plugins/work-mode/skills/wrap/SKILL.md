# 收尾模式（wrap）

使用者準備結束這個對話。**核心前提：對話關掉之後，只在聊天裡講過、沒有寫進檔案的東西都會消失。**用使用者的語言回覆。

## 規則

- **不開新支線**：不提新點子，不做沒有被要求的改進。想到值得做的，只寫進「下一步」。
- 和 auto 模式同時開著時，收尾模式優先：先收，不要再擴張。

## 步驟（依序做，不准跳）

### 1. 做完手上的

把已經開始的工作做到可以交付為止。真的做不完（等使用者回答、缺帳號密碼、外部阻礙），不要靜靜略過，記下來放進收尾單。

### 2. 驗證

每個寫入動作都要讀回確認；改了看得見的東西要實際打開看；部署過的要打開公開網址確認是新內容。沒有驗證過的，不准寫成「已完成」。

### 3. 落地

逐項問自己：「明天這個對話不見了，還找得回來嗎？」

| 類型 | 寫到哪裡 |
|------|----------|
| 做了甚麼、決定了甚麼 | 該專案的 README、日誌或說明文件 |
| 還在等使用者回答的問題 | 寫進對應檔案，不能只在聊天裡問 |
| 未完成的事、下一步 | 該專案的待辦檔 |
| 學到的教訓、使用者的偏好 | 專案的 memory 或 CLAUDE.md |
| 只對這次對話有意義的 | 不用寫 |

拿不準要不要寫，就寫。

### 4. 只提交自己改過的檔（如果是 git 專案）

```bash
git status --porcelain
git add <只加這次對話改過的檔>        # 不准 git add -A
git diff --cached --name-only        # 單獨執行，看清楚
git restore --staged <不是你改的檔>   # 有別人的改動就踢出去
git commit -m "<一句說清楚做了甚麼>"
```

- 檢查和 commit **分開兩個指令**執行，不要用 `&&` 串在一起，否則還沒看清楚就已經提交。
- 同一個專案可能有其他對話同時在改，暫存區是共用的，所以每次 commit 前都要看一次清單。
- 不是你改的檔案留給原本的人，在收尾單註明。
- `git push` 屬於對外動作，除非使用者這次明確要求，否則放進「待你決定」。

### 5. 收尾單

```
🔒 收尾單
✅ 做完了：<3–5 點，每點附驗證證據>
📍 寫進了：<檔案路徑／commit>
🤔 待你決定：
  - <事項>｜我的建議：<建議>｜理由：<一句>
⏭️ 下一步：<下次對話從哪裡接手>
🗑️ 以上都已寫進檔案，可以放心關掉這個對話。
```

「待你決定」只列新的或有變動的事項，每項都要附建議，不要只丟問題給使用者。沒有就寫「無」。
